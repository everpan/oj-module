# ojm build 产物布局：{web,api}/dist → dist/{web,api}

- 日期：2026-10-22 21:00
- 分支：`refactor/dist-layout`
- 状态：已完成（21:25 并入 feat/ojm）

## 背景与问题

`ojm build` 的产物落在源码目录之下：

- 站点产物 `<project>/web/dist/`
- 后端 release 根 `<project>/api/dist/`（manifests.yaml + `<name>-<version>/` 兄弟目录）

产物与源码混在一棵树下，不符合直觉（产物应收在工程根的单一 `dist/` 下），且
`api/dist` 与 `api/src`、`api/config.yaml` 并存，易误删、易进错目录。

## 方案

唯一真源 `layout.ts`（D11：dev/build/preview 对产物路径一律经此模块）：

| 布局 | distDir（站点产物） | apiDist（oj release 根） |
|---|---|---|
| module-root | `<project>/dist/web` | `<project>/dist/api` |
| new（历史 uni-dev） | `<project>/dist/web` | `<project>/dist/api` |
| flat（框架根仓 dogfooding） | `<project>/build`（**维持不变**） | `<project>/dist/api` |

- flat 的 web 产物维持 `build/`：框架根仓自构建约定（vite outDir），不在本次诉求范围；
  仅 apiDist 随全局约定归位，保持「apiDist 不随布局变化」的单一语义。
- 硬编码收编（违反 D11 的存量）：`bundle.ts`（api/dist、web/dist/modules）、
  `contract/check.ts`（api/dist）、`market/walkthrough.ts`（api/dist ×3）一律改走 layout。
  `build.ts`/`preview.ts`/`preview-config.ts`/`dev.ts` 本就走 layout，仅改注释。
- 脚手架 `.gitignore`（init.ts SCAFFOLD + templates 工程）：`api/dist/ web/dist/ modules/dist/` → `dist/`。
- **preview 语义不变**：`runPreview` 的四查（index.html / manifests.yaml）与派生 config 全部
  layout 驱动，产物挪位后自动指向 `dist/web` + `dist/api`，仍是单进程单站点预览。

## 影响面清单（相关功能核查结论）

| 功能 | 是否受影响 | 说明 |
|---|---|---|
| `ojm build` | 是 | layout.ts 真源，自动跟随 |
| `ojm dev` | 否（代码） | dev.ts 走 layout.distDir；本地 `dist/web` 为 dev 中间产物，已被 gitignore 覆盖 |
| `ojm preview` | 否（代码） | 全 layout 驱动；四查/派生 config 指向新路径 |
| `ojm bundle`（方案打包） | 是 | 硬编码收编为 layout 取值 |
| `ojm api --check`（契约对账） | 是 | release 路由表目录改走 layout（无布局时回退旧 api/dist） |
| `ojm merge`（manifest 合并） | 否 | 纯 JSON 合并，不碰产物目录 |
| `ojm info` | 否 | 打印信息 |
| 市场 bootstrap / walkthrough | 是 | walkthrough 断言目录改走 resolveLayout |
| 方案安装器（后端读 versions.json） | 否（代码） | 读 `platform.root`（config），bootstrap 已写 layout 相对路径，自动跟随 |
| templates 工程 | 是 | .gitignore 更新；旧 `web/dist`、`api/dist` 为 gitignored 产物，挪位零残留 |
| e2e（scripts/lifecycle-*.mjs） | 待核查 | 若硬编码 api/dist 需同步（见任务清单） |

## 总结

关键过程：唯一真源 layout.ts 改 `dist/{web,api}`（flat 布局 web 产物维持 build/，apiDist 全布局
归位 dist/api，含无布局回退——保持「apiDist 不随布局变化」的单一语义）。收编三处违反 D11 的
硬编码：bundle.ts、contract/check.ts、market/walkthrough.ts。关键发现：templates 运行期
`marketEnv()`/`solutionsEnv()` 的生产缺省（sharedRoot/siteModulesDir/modulesJsonPath）硬编码
`api/dist`、`web/dist`，相对 fs jail 根（config.yaml 所在目录）解析——不改则新布局下市场安装器
与 solutions API 运行期全哑，已同步改为 `dist/api`、`dist/web/...`（market-api.spec 有缺省值钉面）。
preview 全程 layout 驱动零改动，四查/派生 config 自动指向新路径。脚手架与 templates 的
.gitignore 收编为一条 `dist/`。

回归：packages/cli 397 passed、tests/cli + tests/runtime 645 passed、templates 612 passed、
根 typecheck 绿（需 8G 堆，既有现象）。

耗时：约 85 分钟（调查与影响面 20' + 文档 10' + TDD 与实现 35' + 回归 20'）。
