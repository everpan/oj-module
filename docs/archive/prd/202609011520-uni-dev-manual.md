# uni-dev 使用手册（ram CLI）

> 适用版本：`@react-antd-module/cli@0.1.1`（npm 已发布，内置 oj v0.1.0）。
> 读者：模块开发者 / 接入方工程维护者。配套设计文档：`202609011158-uni-dev-design.md`，
> 实现计划与阶段小结：`202609011243-uni-dev-plan.md`。

uni-dev 是「前后端一体化模块工程」开发链：一条 `ram` 命令把
**前端模块（React 19 + antd 6，宿主 shell 预构建 + importmap 共享依赖）**
与 **后端（oj：Rust+V8，JS 即接口）** 装配进同一个工程，dev/build/preview 全链可用。

---

## 1. 快速开始

cli 已发布到 npm（`@react-antd-module/cli`），两种引导方式任选：

**流程 A（推荐）：免安装直跑**

```bash
mkdir my-app && cd my-app
pnpm dlx @react-antd-module/cli init ./ --yes   # 或 npx @react-antd-module/cli init ./ --yes
pnpm install
pnpm dev                # http://localhost:5174 ，登录 admin / 123456
```

**流程 B：cli 装为项目依赖**

```bash
mkdir my-app && cd my-app
pnpm add -D @react-antd-module/cli
# pnpm v11 在 esbuild 构建审批写入前会拦截 `pnpm ram …`（ERR_PNPM_IGNORED_BUILDS），
# 首次 init 用 node 直跑 bin 绕过：
node node_modules/@react-antd-module/cli/bin/ram.mjs init ./ --yes
pnpm install            # init 已把 allowBuilds.esbuild 审批合并进 pnpm-workspace.yaml
pnpm dev
```

> init 幂等：已存在的文件一律跳过只补缺；`package.json` 已存在时**合并补缺**
>（scripts/devDependencies 只补缺失键，既有内容永不覆盖）；重跑安全。

四步之后你得到：可登录的管理台（demo 模块）、热更的前端模块链、
热更的 oj 后端（改 `api/src/**` 保存即生效）、sqlite 本地库。

## 2. 命令一览

| 命令 | 作用 | 默认端口 |
|---|---|---|
| `ram init [dir] [--yes]` | 脚手架；已存在的文件跳过（幂等补缺） | — |
| `ram dev [port]` | 开发服：静态（模块 dist 优先，shell 兜底）+ `/api` 反代 oj + 模块 watch 重建 + SSE 页面自刷 | 5174（占用自动顺延） |
| `ram build` | 后端 `oj build`（零 DB 副作用）→ 前端模块构建 → 全站合并清场 | — |
| `ram preview [port] [--oj-static]` | 生产形态预览：`oj migrate` → `oj server` + ram 静态兜底（SPA fallback） | 4173 |
| `ram info` | 版本矩阵 + 模块清单 + oj 版本/证书观测（报障时完整粘贴输出） | — |
| `ram api` | 契约代码生成：client.ts / client.schemas.ts / routes.json / openapi.yaml + 后端 api.ts stub（幂等） | — |
| `ram api --check` | 契约对账门禁：生成物过期 / route 双向不一致 / routes.js drift 即 error 退出 1 | — |
| `ram api --docs` | 聚合全部契约渲染 redoc 静态文档站（uni-dev 落 `api/docs/`，纯前端落 `docs/api/`） | — |
| `ram merge <out.json> <in1.json> [...]` | 合并多团队 modules.json（同名模块显式拒绝） | — |

无参数或未知命令打印 usage 并退出（未知命令退出码 1）。

## 3. 工程布局（ram init 产物）

```
my-app/
├── bin/oj                 # oj 真二进制（随 ram 内置 vendor tarball 解出）
│   └── devkit/api-manual.md
├── api/
│   ├── config.yaml        # oj 服务配置（端口/base/密钥/证书路径）
│   ├── config/            # 证书三件套：cert.jws / public.pem / private.pem（按工程现铸）
│   └── src/web/           # 后端接口源码（JS）：hello、user-info、get-async-routes
│       ├── contract.ts    # 模块契约（defineApi + zod schema，前后端单一事实源）
│       ├── routes.json    # ram api 生成的路由表（oj build 经 .route 对账）
│       ├── manifest.yaml
│       ├── migrations/0001__create_users.sql   # 建表（仅 DDL）
│       └── seed.sql                              # 种子数据（仅数据，禁 DDL）
├── modules/
│   ├── src/demo/          # 前端模块（entry.ts 是元数据唯一来源）
│   │   └── api/           # 契约目录：contract.ts 手写，client.ts 等由 ram api 生成（勿手改）
│   └── dist/              # 模块产物（ram dev/build 生成）
├── modules.config.ts      # 模块清单（entry 相对工程根）
└── package.json / tsconfig.json / global.d.ts / .gitignore
```

约定要点：

- **模块 entry 只 import 三类**：`@react-antd-module/runtime`、共享依赖（宿主 importmap 提供，不进 dependencies）、自身相对路径。
- **布局三段**：`handle.layout`（`container`/`parent`/`none`，默认 `none`）由框架出口统一包裹，模块不 import 布局组件。
- **seed.sql 只放数据**：含 DDL 会被 `oj build` 拒绝；建表放 `migrations/`，文件名形如 `0001__create_users.sql`（desc 段仅允许 `[A-Za-z0-9_]`，连字符非法）。
- **config.yaml 内相对路径相对文件所在目录**；`server.host` 显式钉 `127.0.0.1`（oj 默认绑 `[::1]`，localhost 解析序在反代下有坑）。

## 4. ram dev（日常开发）

```bash
ram dev          # 或 ram dev 5200
```

- 启动顺序：oj 健康就绪（`GET {base}/health`）→ 静态服 → watch。
- `/api/*` 反代到 oj（默认 `127.0.0.1:9778`），其余静态请求：模块 `modules/dist` 优先、shell dist 兜底，全部 `no-store`。
- HTML 经外链脚本 `/__ram_reload.js` 注入 SSE 通道；改 `modules/src/**` 触发重建后页面自动刷新。watch 目标随布局（`modules/src`、`api/src`）。
- **契约 watch**：任何 `contract.ts` 变更自动重跑 `ram api` 重生成（防抖 100ms，运行中变更不丢）；契约驱动 mock 同步热载——手写 mock 未命中的路由按契约 `data` schema 生成示例数据兜底。
- Ctrl-C 按 SSE hub → oj → 静态服 顺序回收，不留孤儿进程；9778 被占用时启动即报人话错误（不静默换端口）。

### 登录链（首跑闭环）

`POST /api/auth/login`（`{"username":"admin","password":"123456"}`）→
oj 原生信封 `{code:0,msg,data:{access_token,refresh_token}}`。
runtime 在 api 层归一化为框架 `ApiResponse`（`result.token/refreshToken`），
消费方零感知。端点映射：

| 框架语义 | oj 端点 |
|---|---|
| 登录 / 登出 / 刷新 | `auth/login` / `auth/logout` / `auth/refresh`（无模块段） |
| 用户信息 / 动态路由 | `web/user-info` / `web/get-async-routes`（必含模块段） |

## 5. ram build / preview（生产形态）

```bash
ram build        # 产物：modules/dist/（含 index.html、modules.json）+ api/dist/manifests.yaml
ram preview      # migrate → oj server + ram 静态兜底
```

- 全站合并（清场 + 拷 shell dist）**只属 build**；dev 热重建不合并（dev 的 `/` 直接服务 shell dist）。
- `preview` 先 fail-fast 四查：`bin/oj`、`api/config.yaml`、`modules/dist/index.html`、`api/dist/manifests.yaml` 缺一即人话报错（提示用 `ram build`/`ram init` 补缺）；`oj migrate` 非零退出则透传 stderr 且不起 server。
- 默认静态由 ram 兜底：history 深链接（如 `/demo`）回落 `index.html`。

## 6. ram info（报障）

输出版本矩阵（cli/runtime/shell）、共享依赖版本表（宿主 versions.json）、
模块清单，以及后端观测段：内置 oj 版本 vs 现场 `bin/oj -V`（不一致标 `[!]` 漂移提醒）、
`api/config.yaml` 解析出的 port/base、`/health` 证书状态与到期时间。
**服务未运行时证书行显示「无法探测」属正常**，起服后可测。任一观测不可达仅告警，不失败。

## 7. 注意点（务必阅读）

1. **依赖钉版告警**：init 时若 `@types/react`/`typescript` 未在宿主 versions.json 中，模板回退 `"*"` 并告警——`pnpm install` 后请手动钉到宿主矩阵版本，避免与 shell 内建实例漂移。
2. **`--oj-static` 的已知限制**：该选项把静态直出交给 oj（`--app-path modules/dist`），history 深链接会 404；ram 本口仍保留 SPA 兜底与 `/api` 反代，日常预览**不需要**加它。
3. **jwt_secret 必须更换**：init 随机生成仅为开发用，生产部署前换 `api/config.yaml` 的 `auth.jwt_secret`。
4. **证书按工程现铸**：每个工程 init 时生成独立证书三件套，不跨工程复用；`ram info` 可查到期时间。
5. **9778 占用不静默换端**：oj 端口被残留实例占用时 dev/preview 直接报错——先 `lsof -i:9778` 清残留（旧版本杀外层 ram pid 不杀进程组可能留孤儿，现版本已修复为信号转发 + 进程组回收）。
6. **mock 不进生产**：fake server 仅 dev 启用；生产构建需显式 `VITE_ENABLE_FAKE_PROD=1` 才会包含（有测试断言产物无 fake 代码）。
7. **legacy 布局删除里程碑**：`modules/demo`（无 `src/` 段）旧布局兼容分支将在**下个 minor 版本删除**，请按 §3 新布局迁移（playground 已迁移，参照 `apps/playground/modules.config.ts`）。
8. **CI 无产物环境**：真二进制冒烟（`tests/integration/uni-dev-smoke.test.ts`）依赖本仓 vendor tarball 与 shell dist，CI 或 9778 被占用时自动跳过。
9. **报障**：直接粘贴 `ram info` 完整输出给框架团队（包内不发源码/map，这是唯一环境指纹）。
10. **pnpm v11 构建审批**：v11 起 `package.json` 的 `pnpm` 字段被废弃，esbuild 的 postinstall 审批只读 `pnpm-workspace.yaml` 的 `allowBuilds`。init 已自动落模板并合并审批；若你手工建工程，缺了它会全员报 `ERR_PNPM_IGNORED_BUILDS`。另外 v11 首次 install 会自动生成 `pnpm-workspace.yaml`（含占位行），init 重跑会把占位行填成 `esbuild: true` 并保留其它键。

## 8. 常见问题

| 现象 | 原因与处理 |
|---|---|
| `找不到 @react-antd-module/shell 的预构建产物（dist）` | 0.1.0 的 init 钉版缺陷，0.1.1 起内置矩阵兜底；升级 cli 即可 |
| `ERR_PNPM_IGNORED_BUILDS` | pnpm v11 拦截了 esbuild postinstall：`pnpm-workspace.yaml` 补 `allowBuilds: {esbuild: true}`（init 会自动合并，见注意点 10） |
| `版本矩阵门禁（C4/D12）校验失败` | shell dist 与已装依赖版本不一致：`ram info` 对账，按提示对齐版本重装 |
| 登录 401 循环刷新 | oj 未就绪或 base 不配：查 `ram info` 的 port/base 行与 `/api/health` |
| 改后端接口不生效 | 确认改的是 `api/src/**` 且保存后终端有 oj 热更日志；`api/dist` 是 build 产物，dev 不读 |
| 深链接 404 | 加了 `--oj-static`（见注意点 2）；默认模式不存在此问题 |
| `ram merge` 报同名模块 | 设计如此：多团队清单同名必须人工裁决，不静默覆盖 |
