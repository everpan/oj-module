# ram api 支持指定项目目录

日期：2026-09-03 20:19
分支：feat/ram-api-cwd
前置：docs/prd/202609031808-cli-subcommand-help.md（帮助体系，独立分支）

## 背景

`ram api` 目前固定以 `process.cwd()` 为项目根，在 monorepo 根目录或 CI 中无法对子工程（如 `apps/playground`）单独跑契约生成/对账，必须 `cd` 进去。`runApi` / `runApiDocs` / `checkApi` 本就接收 `cwd` 参数，缺的只是 CLI 参数透传。

## 需求（BDD）

### Feature: ram api 指定项目目录

| # | 场景 | 输入 | 期望 |
|---|------|------|------|
| S1 | 缺省目录 | `ram api` | cwd 为项目根（行为不变） |
| S2 | 位置参数目录 | `ram api apps/playground` | 以解析后的该目录为项目根执行生成 |
| S3 | 目录 + flag 混排 | `ram api --check apps/playground` / `ram api apps/playground --check` | 目录与 `--check` 均生效 |
| S4 | --docs / --check 同样支持目录 | `ram api docs-dir --docs` | 文档站生成到指定工程下 |
| S5 | 目录不存在 | `ram api /nonexistent` | 报清晰错误、非 0 退出（不静默跑错目录） |

### 参数约定

沿用 `parseInitArgs` 既有约定：位置参数取第一个不以 `--` 开头的参数，`--xxx` 一律开关。

## 设计

- `args.ts`：新增纯函数 `parseApiArgs(argv): { dir, check, docs }`。
- `index.ts` api 分支：`dir ? path.resolve(dir) : projectRoot`；dir 非空时先 `fs.existsSync` 校验（S5）。
- `usage.ts`：用法行改 `ram api [dir] [--check] [--docs]`。

非目标：不支持 `--cwd` 长选项（与 init 的位置参数风格保持一致）；其他子命令（dev/build/preview）不在本次范围。
