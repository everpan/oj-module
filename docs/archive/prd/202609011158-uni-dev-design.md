# 前后端统一开发工具（uni-dev）设计

> 需求源：`docs/prd/uni-dev.md`。本文是经脑暴确认后的设计方案，实现计划另出。
> 关键决策 D1–D7 经脑暴逐条确认；2026-09-01 第一轮审阅补充 D8–D9；同日第二轮
> 双角色评审（架构师 + 开发工程师，实测 oj v0.1.0 全链）修订 D6/D9、补充 D10–D11，
> 全部记录见 §11。

## 1. 背景与目标

`@react-antd-module/cli`（ram）目前只覆盖前端模块工程（dev/build/info/merge）。
oj（only-js，Rust 内嵌 V8 的 JS/TS 后端框架）提供了后端能力：目录镜像路由、
dev 模式 `.ts` 直跑热更、`oj build/migrate/server` 发布链。

本需求把两者统一：**开发者只用 ram 四个命令（init/dev/build/preview）即可完成
前后端一体化工程的创建、开发、构建与预览**，oj 作为实现细节被 ram 编排。

## 2. 已确认决策

|---|---|---|

| D7 | 后端构建器 | 维持 `oj build`（见 §7 论证），vite 只负责前端模块 |

## 3. 工程布局（ram init 产物）

```text
<name>/
├── bin/                    # init 解 tar.gz（sha256 校验 → 系统 tar --strip-components=1）：
│                           #   oj 二进制 + plugins/ + devkit/；不入库（.gitignore）
├── api/
│   ├── config.yaml         # oj 配置：host 127.0.0.1（oj 实测默认绑 [::1]，显式钉死防
│   │                       #   localhost 解析序错位）、base "/api"、port 9778、
│   │                       #   sqlite DSN、证书两路径；含 auth 段（jwt_secret 由 init
│   │                       #   随机生成，启用 oj 内置 /auth/* 路由 + Bearer 守卫，
│   │                       #   /auth/* 内置路由不设防，业务端点受真鉴权保护）
│   ├── config/             # init 现场签发证书三件套（D6，非 vendor 分发）
│   ├── src/demo/           # 示例后端模块（manifest.yaml + api.ts），端点含
│   │                       #   /web/user-info、/web/get-async-routes（oj 目录镜像路由
│   │                       #   必含模块段 {base}/{module}/{path}——实现期发现；
│   │                       #   oj 原生信封，由 D10 适配层转换）与演示业务端点
│   │                       #   /web/hello；api/seed.sql 灌 admin 演示用户
│   ├── db.sqlite           # 运行时生成（sqlite DSN 相对 config.yaml 所在目录）
│   └── dist/               # oj build 产物（ram build 生成）
├── modules/
│   ├── src/demo/           # 示例前端模块（entry.ts + pages/ + locales/）
│   └── dist/               # 完整站点（ram build 合并 shell 产出，见 §5）
├── .claude/skills/oj-api-dev/  # devkit SKILL.md + api-manual.md（init 拷贝）
├── modules.config.ts       # 沿用现有约定
├── package.json            # scripts: dev/build/preview/info；依赖版本**钉死精确值**
│                           #   （以 shell dist versions.json + 本机 @react-antd-module/*
│                           #   实装版本为准；workspace:*/catalog: 外部不可解析，
│                           #   @react-antd-module/* 发版是 init 可用的前置里程碑）
├── .gitignore              # bin/、api/db.sqlite、api/logs/、api/dist/、modules/dist/、
│                           #   .ram-tmp-*
├── tsconfig.json
└── global.d.ts             # 拷自 devkit，oj 全局对象类型提示
```

init 幂等：落到非空目录时确认/中止；对既有工程重跑仅补缺（extract-only repair，
不覆盖 config.yaml 与用户代码）。

## 4. ram dev（双进程 + 自动刷新）

```text
ram devServer :5174
  /             → shell index.html（注入外链刷新脚本）
  /assets/*     → shell dist
  /__ram_reload.js → 刷新脚本（静态 JS 端点）
  /modules*     → modules/dist（watch 重建，300ms 防抖）
  /api/*        → 反代到 http://127.0.0.1:<ojPort>（node:http 双向 pipe，不引依赖）
  /__ram_reload → SSE 通道（text/event-stream，15-25s 心跳防中间缓冲）

bin/oj server :9778（ram 拉起的子进程）
  -c <abs api/config.yaml> -b /api --api-path <abs api/src>
  # -b 钉住反代前缀契约（CLI 覆盖 config）；无 manifests.yaml → dev/ts 模式，
  # api.ts 热更为 oj 原生能力
```

启动序列：

1. **Preflight**：`bin/oj`、`api/config.yaml` 与 `api/src` 都在 → 全栈模式；缺任一 →
   退化前端-only 模式（`mock/*.mock.mjs` 接管 `/api`，与现状完全一致）并打警告。
2. **拉起 oj 子进程**：端口用正则从 `api/config.yaml` 读 `server.port`（限 `server:`
   块，注释/引号/嵌套进单测；**miss 直接报错退出**——config 由 init 生成，miss 即被
   手改，静默回落只会与实际监听端口错位，oj 代码默认 778 而非 9778）；`--api-path`
   传绝对路径（oj 的命令行相对路径相对 CWD、config 内相对路径相对 config 所在
   目录，双语义易错，统一绝对路径后规则只剩一条，与 §6 一致）；oj stdout/stderr
   加 `[oj]` 前缀透传；拉起后轮询 `{base}/health`（500ms 间隔、**10s 上限**，期间
   先判子进程存活：已退 → 透传 stderr 非零退出；仍存活但拒连 → 继续到上限），
   就绪才打印启动完成（避免 oj 未就绪时浏览器首批 `/api` 请求吃 502）。
3. **devServer 增量**（复用现有 `dev.ts`；口径为三块功能，实际触点 ≥6 处：
   localDist 服务根、两处 buildModules 调用、watch 目录、build.ts 输出目标、
   SSE 端点、oj 编排新文件）：
   - `/api/*` 由 mock 改为反代（仅全栈模式；前端-only 模式维持 mock 行为）。
     反代规格：req/res 双向 pipe 不缓冲（保留 oj 将来的流式/SSE 响应）；剥
     hop-by-hop 头（connection/keep-alive/transfer-encoding/upgrade/te/trailer/
     proxy-*）；Host 改写为目标端口；上游 ECONNREFUSED/ECONNRESET → 502 JSON；
     全局 `Cache-Control: no-store` 对反代响应同样生效（dev 下无害）；
   - 自动刷新：**shell 产物 CSP 为 `script-src 'self' + 随机 nonce`（每次构建
     重新生成且有测试把守），内联注入脚本必被静默拦截** → 服务 index.html 时在
     `</body>` 前注入外链 `<script src="/__ram_reload.js"></script>`（index.html
     主路径与 SPA fallback 两处），脚本内 `new EventSource('/__ram_reload')`，
     收 `reload` 事件即 `location.reload()`（`connect-src 'self'` 放行同源
     EventSource）；模块重建成功后广播，失败不广播（旧产物继续服务，终端报错
     ——延续现有行为）；
   - watch 目标布局感知（抽纯函数 `resolveWatchTarget(projectRoot)` 便于单测）：
     新布局 watch `modules/src`，旧布局维持 `modules/`。新布局下重建产物写在
     `modules/dist`，沿用现 watch `modules/` 会把自身产物当源码变更，造成自触发
     重建循环（第一轮审阅发现）。
4. **退出回收**：SIGINT/SIGTERM 先 kill oj 子进程再退出，不留孤儿占 9778；
   preflight 探测到 `{base}/health` 已有响应时提示「疑似上次 ram dev 残留实例」。

有意不做：完整 HMR（react-refresh preamble / dev-runtime 映射）维持设计文档
P5 偏差结论，整页 reload 已覆盖「保存即见效果」；`mock/` 与 oj 不叠加——有 oj
时 `/api` 全部反代，心智模型唯一（auth 链走 oj 真鉴权，D10）；WS 不代理
（node:http 有 upgrade 事件、缺便利封装，约 30 行 socket 双向管道，需要时补）；
**后端结构性变更不热更需重启 `ram dev`**（oj 热更边界：新增/删除模块目录、
schema.yaml/migrations、config.yaml、node_modules 变更均重启生效，写进模板
SKILL/README）。

## 5. ram build

1. **后端**（`api/src` 存在时）：
   - `bin/oj build -d <abs api/src> -o <abs api/dist>`；
   - 不跑 migrate（D8）：`oj build` 本身零磁盘副作用，`ram build` 保持零 DB 副作用
     （CI/无 DB 环境可跑），迁移账本由 preview 在起服务前应用（§6）。
2. **前端**：合并输出 `modules/dist` 完整站点，**合并只属于 `ram build`**
   （devServer 的热重建路径只写 `modules.json` + `modules/` 模块产物——dev 的
   `/`、`/assets/*` 直接服务 shell dist，全量拷贝在 dev 路径无人消费，且会让每次
   热重建都拖上 shell dist 拷贝）：
   - 先清空 `modules/dist`（shell 每次重构建生成新哈希资产名，不清场旧资产无限
     累积），再拷 shell dist 全量（`index.html`、`assets/`、`versions.json`、
     favicon 等）；
   - 再写入 `modules.json` 与 `modules/<name>/` 模块产物。
   - 产物自包含、可独立部署，preview 的静态根直指它。
3. 无 `api/src` → 跳过后端构建，纯前端工程照常可用。

## 6. ram preview

默认形态（D9 修订）：

```bash
bin/oj migrate -c <abs api/config.yaml> -d <abs api/dist>   # D8：先迁移再起服务
bin/oj server -c <abs api/config.yaml> --api-path <abs api/dist>   # 仅 API
ram 静态服务（复用 devServer 静态半边：SPA 回退、不注入 SSE、可去 no-store）
  → 静态根 = modules/dist，/api 反代到 oj
```

- **默认 ram 静态层兜底**：与 oj 手册 §13「SPA 回退经前置反代补」的官方姿势一致，
  dev 与 preview 行为对称；oj 仅承担 API（release/js 模式）。
- `--oj-static` 选项切换为 oj `--app-path <abs modules/dist>` 直出（真 exercise oj
  静态层，history 路由下刷新/深链接 404）；oj 侧补 SPA 回退立项（维持）后可切回默认。
- 一律传绝对路径，避开 oj「命令行相对 CWD / config 内相对 config 目录」的双语义
  歧义（含 `-c`，与 §4 一致）。
- 先 `oj migrate` 再 `oj server`：对齐 oj 部署公式 `build && migrate && server`，
  release 的 verify 迁移门禁由 migrate 先行满足；**migrate 非零退出 → 透传 stderr、
  ram 非零退出、不起 server**（M004 报错文案 oj 自带，透传即可）。
- 启动前 fail-fast 四查：`bin/oj`、`api/config.yaml`、`modules/dist/index.html`、
  `api/dist/manifests.yaml`，缺一即提示对应补救（build / init repair）。

## 7. 后端构建器论证（D7）

不统一用 vite 编译后端。`oj build` 不是 TS 转译器，而是 oj 框架的发布契约：

1. `manifests.yaml` 锁：oj server 靠它判定 release/js 模式（`server_cmd::is_release`）；
2. `routes.js` 路由表 + `.route` 剥离：release 下参数路由以 routes.js 为准；
3. 版本目录聚合 + 结构检查（`--check`：表归属、跨模块 deps、seed 纪律）；
4. `oj migrate` 的迁移账本挂在 dist 产物上。

vite 只能完成其中转译一环，其余产物无法生成，与 oj 运行时契约对不齐。前后端的
一致性在「都只写 JS/TS」这层（oj 的核心卖点），而非同一个构建器。
（第二轮评审实测：绝对路径 build/migrate/server 全链通、release 自动判定成立。）

## 8. 错误处理

| 场景 | 行为 |
|---|---|
| `bin/oj` 缺失 | 人话报错并指向 `ram init` **幂等补缺**（extract-only，不覆盖 config/用户代码；「重新 init」会覆盖脚手架，禁止原样建议） |
| oj 子进程启动即退（证书/DB/端口） | 透传 oj stderr，ram 非零码退出 |
| `api/config.yaml` 缺 `server.port`（正则 miss） | **报错退出**并提示检查 `server.port`（config 由 init 生成，miss 即被手改；oj 代码默认 778） |
| health 轮询超时（10s） | kill oj 子进程、dump 其 stderr 尾部、提示检查 config 的 host/port |
| 反代上游拒连（ECONNREFUSED） | 502 JSON + 提示（含 127.0.0.1/[::1] 绑定错位排查线索） |
| preview migrate 失败 | 透传 stderr、ram 非零退出、不起 server |
| devServer 端口占用 | 现有顺延逻辑不变 |
| 模块重建失败 | 终端报错、不广播 reload、旧产物继续服务 |
| tar.gz 平台不符（包内为 mac 二进制/dylib） | 现阶段仅支持 macOS，init 时 `process.platform` 检查并明说；系统 `tar` 缺失时一并报错 |
| init 落非空目录 | 确认/中止守卫 |

## 9. 测试

**前置 spike（PR0，半天，实现计划首项，结果门禁后续 PR）**：node:crypto 签发
三件套 → 模板 config 起 `oj server` → curl `{base}/health` 与一条业务路由；复验
JWS payload schema（exp/nbf）、auth 段下 `/health` 匿名性。通过后冻结实现。

- **单测**（Vitest，沿用 `tests/cli/*.test.ts` 约定）：
  - init：脚手架产物存在性与关键内容（config.yaml 的 host/base/port/auth 段、
    证书三件套现场签发、SKILL.md 拷贝、示例模块、.gitignore、package.json 版本
    钉死来源）；非空目录守卫；幂等补缺；
  - devServer（给 `devServer()` 加 opts 注入口注入 oj port/base，桩 HTTP server
    冒充 oj）：`/api` 反代断言（转发、头透传、502、流式不缓冲）；外链
    `/__ram_reload.js` 注入两处（主路径 + SPA fallback）；`resolveWatchTarget`
    纯函数断言（新/旧布局）；端口正则三 case（注释/引号/嵌套）；health 轮询
    超时与子进程存活分支；
  - build：合并后 `modules/dist` 目录结构断言 + **清场断言**（旧哈希资产不残留）
    + 零 DB 副作用断言（不 spawn migrate）；
  - preview：spawn 参数与顺序断言（绝对路径、migrate → server、静态根指向）、
    migrate 失败分支断言；
  - runtime 信封适配（D10）：`result ?? data` 兼容读、字段映射、新端点指向。
- **e2e**（本机可跑，CI 跳过）：tmp 目录 `ram init` → `ram dev`（全栈）**首跑
  UI 登录闭环**（登录 → 拿到模块路由 → 渲染 demo 页）→ `ram build` → preview
  冒烟（curl `/`、登录链、一条业务 API）。

### 发布实测记录（2026-09-01，npm 0.1.0 发布后 /tmp 全流程验证）

0.1.0 三包发布后用真实 npm 包在 /tmp 走外部用户全流程，暴露 3 个缺陷，
全部 TDD 修复并随 0.1.1（shell/cli）重发：

| # | 缺陷 | 根因 | 修复 |
|---|------|------|------|
| P1 | `ram init ./ --yes` 整体跳过已存在的 `package.json` → `pnpm dev` 无脚本 | 「已存在即跳过」对 package.json 粒度过粗：外部用户常先建最小 package.json 装 cli | 合并补缺：`mergePackageJson` 只补缺失键（scripts/devDependencies），既有键永不覆盖 |
| P2 | 外部工程 init 直接 throw「找不到 shell dist」 | 钉版数据源只有 shell dist：发布包无 monorepo 兄弟目录、目标工程尚未 install——鸡生蛋死锁 | `resolveVersionMatrix` 三级回退，cli 内置 `vendor/host-versions.json`（`scripts/sync-host-versions.mjs` 从 shell dist 同步，挂 prepack 钩子发布前必新） |
| P3 | `pnpm install` 后所有 pnpm 命令报 `ERR_PNPM_IGNORED_BUILDS` | pnpm v11 废弃 package.json 的 `pnpm` 字段，esbuild postinstall 审批只读 `pnpm-workspace.yaml`；且 v11 首次 install 自动生成带占位行的 workspace yaml，把模板的「已存在即跳过」挡在门外 | 新增 `templates/pnpm-workspace.yaml` + `ensureAllowBuilds` 合并（占位行填 true、无段追加、显式 false 尊重不动） |
