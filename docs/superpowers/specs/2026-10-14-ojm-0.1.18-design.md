# ojm 0.1.18 设计：oj 0.1.69 对齐 + 通知模板同步 + beforeClose 标签守卫

日期：2026-10-14
分支：`feat/ojm-0.1.18`
锁步发版：`@oj-module/runtime` 0.1.17 → 0.1.18，`@oj-module/cli` 0.1.17 → 0.1.18

## 背景

1. **oj 发布 0.1.69**（repo 门禁钉在 0.1.50）。其中 v0.1.64 引入**嵌套 handler 组**，
   官方手册给出明确的 DDD 落点映射（限界上下文=模块、聚合根=实体组、同聚合多动词
   应收进单文件嵌套组而非动词子目录）。模板 api.ts 全部是动词目录形态，需按 DDD 判据 reshape。
2. **runtime 通知铃已升级**（f05b3deb、628e31cc：按人通知 + 广播表 + push/del 原语 +
   markRead 归属 403），但 init 模板的后端只同步了 client/contract，后端 handler、
   `_shared`、migrations 0002/0003 均缺失，`ojm init` 出来的工程通知面是坏的。
3. **模块需要拦截标签页关闭**（oj-wiki 已落地参考实现并提 PR）：有未保存改动时
   弹确认框，removeTab 先删页签再导航会导致 keep-alive 缓存销毁、组件卸载，
   `useBlocker` 来不及触发。正确做法：运行时真正移除页签**之前** await 模块守卫。

## 已确认的决策（与需求方对齐）

| 问题 | 决策 |
|---|---|
| Item 1 改造范围 | 全模板 DDD 改造（_platform / auth / notification / personal-center / web），playground-oj 同步，MIN_OJ_VERSION 抬 0.1.69 |
| Item 2 基线 | 全量对齐 playground-oj 的 notification 后端 |
| 钩子触发面 | 五个关闭动作全罩；任一守卫否决 → 整批取消（事务式） |

## Item 1 — oj 0.1.69 对齐 + 全模板 DDD 改造

### 版本与门禁

- `packages/cli/src/vendor.ts`：`MIN_OJ_VERSION` 0.1.50 → **0.1.69**（既定政策：钉最新发布版）。
- playground-oj `bin/` vendored oj 升 0.1.69（`ojm vendor` / `.oj-version`）。
- 模板 `api/config.yaml` 核对：mounts 模型（0.1.58）已采用；0.1.59–0.1.69 无新增必填配置项
  （嵌套组、统一占位符、`default` 注解均为代码层特性）。config.yaml 注释补充 0.1.64 嵌套组说明。

### api.ts reshape 原则

依据手册判据：**同聚合操作进同一实体组，不同聚合才拆目录**。组名 = 路径段，
故路由路径不变、`routes.json` 不变、`ojm api --check` 双向对账预期自然保持全绿。

| 模块 | 现状（动词目录） | DDD 形态（嵌套组，路由路径全部不变） |
|---|---|---|
| `notification` | `notifications/{api.ts(get), read/, read-all/, clear/}`、`push/`、`push-broadcast/`、`del/` | 模块根单文件 `api.ts`：`notifications` 组（get + `read`/`read-all`/`clear` 子组）+ `push`/`push-broadcast` 单动词组（连字符组名用字符串字面量键书写）；**`del/` 保留独立目录作为唯一例外**——`del` 是 oj 保留动词键（动词键下不允许挂子组，装配期硬报错），不能作组名；删除其余动词子目录；`_shared/` 保留，引用深度由 `../_shared/notify` 变 `./_shared/notify` |
| `auth` | `login/`、`logout/`、`refresh/` | 模块根单文件 `api.ts`：`login`/`logout`/`refresh` 三个单动词组（会话聚合的三操作）；`_shared/session.ts` 保留。护栏：api.ts 只收会话生命周期操作，未来的 register/reset/oauth 属新聚合、各自开目录 |
| `personal-center` | `upload/api.ts` | **不变**——单聚合单端点，已是最简形态（手册判据：≤3 动词单一聚合可平铺/单文件） |
| `_platform` | 仅 schema/migrations/seed，无 handler | **不变**——无 api.ts 可 reshape |
| `notifications`（root 兜底） | 单文件 get | 不变（单端点，`.ojm-api-exempt.json` 豁免照旧） |
| `web` | `get-async-routes/`、`hello/`、`user-info/` 单动词目录（异聚合平铺） | 不变——单动词目录即「单端点独立聚合」最简形态，无组可收 |

playground-oj 额外的 `demo/`、`home/`、`system/` 模块按同一判据 reshape（system 为
主要工作量，实施计划中逐聚合拆分）。`_shared/` 目录不受嵌套组影响（无尾下划线，
不会被当成 `_name_` 路径参数）。

**注意**：oj 手册明确嵌套组上限 4 层、`route`/`schema` 为保留键；改造不得触碰这些红线。
release 下路由事实唯一来源是 `routes.js`——playground-oj 若发 release 产物需重新 `oj build`，
dev 形态无此步骤。

**聚合论证（评审 m3 补笔）**：notifications 表是一致性边界=一个聚合，
读/已读/清空/推送/删除都是该聚合上的操作；广播表（migrations 0003）在文件内作 sibling 组——
发射三端点是薄 HTTP 壳、真逻辑在 `_shared/notify.ts`，单文件 ~300 行可控。
严格按手册「独立聚合→独立目录」把 broadcast 拆出去亦可辩护，但手册同时明确
「文件过胖是聚合过胖的信号，不是回退动词目录的理由」，且鉴权差异（401/403 归属）
在 handler 内处理、与文件布局无关，故选单文件。

### checker 连字符组键支持（评审 B1，blocker）

`ojm api --check` 的 AST 扫描（`packages/cli/src/contract/check.ts:264` `walk()`）
只认 identifier 键——字符串字面量组键（`"push-broadcast": {...}`）被直接跳过，
`dottedNameOf` 也不支持元素访问。若不动 checker，reshape 后这些 handler 对双向对账
**完全隐形**：契约侧报 route-not-implemented（warn 级，`index.ts:87-90` 只对 error
退 1，极易被忽略），handler 侧 route-unregistered 永不触发，「全绿」验收失效。

**处置：修 checker，不让全库迁就 workaround**（cli 本就随本次发版）：
- `walk()` 接受 `ts.isStringLiteral(prop.name)`（一行），字符串键与标识符键同等解析。
- **保留限制并写入文档**：元素访问式元数据（`api["push-broadcast"].route = ...`）
  仍不支持——reshape 的授权形态是字符串字面量键 + 组内函数挂 `.route`（属性访问式）。
- 新增 `tests/cli/contract-nested-groups.test.ts`：连字符字符串键组的 route 对账用例，
  防回归（现有 `template-notification.test.ts` 只断言 error 为零，拦不住 warn 级失明）。

## Item 3 — 标签页关闭前守卫 `beforeClose`

采用 oj-wiki PR 形态 + 数组注册增量。改动文件：`packages/runtime/src/store/tabs.ts`。

### 类型

```ts
export type BeforeTabCloseGuard = () => boolean | Promise<boolean>;

export interface TabItemProps extends Omit<TabPaneProps, "tab"> {
    key: string;
    label: React.ReactNode;
    draggable?: boolean;
    historyState?: Record<string, any>;
    /**
     * 关闭该标签页（含关闭右侧/左侧/其他/全部）前调用，顺序 await。
     * - 返回 false / reject / Promise<false> ⇒ 中止本次关闭（标签页保留）。
     * - 返回 true / Promise<true> ⇒ 允许关闭。
     * 数组注册：多守卫顺序执行，任一否决即整批取消。
     * 传 null 显式清除该页签全部守卫（含其他模块注册的）。
     */
    beforeClose?: BeforeTabCloseGuard | BeforeTabCloseGuard[] | null;
}
```

`TabStateType extends Omit<TabItemProps, "label">` 自动继承。

### guardClose（模块作用域，与 store 同文件）

```ts
const guardClose = async (get: () => TabsStore, keys: string[]): Promise<boolean> => {
    for (const key of keys) {
        const fn = get().openTabs.get(key)?.beforeClose;
        if (!fn) continue;
        const fns = Array.isArray(fn) ? fn : [fn];
        for (const f of fns) {
            try {
                if (!(await f())) return false;
            }
            catch (e) {
                console.error("[tabs] beforeClose 守卫抛错，按中止关闭处理", e);
                return false;
            }
        }
    }
    return true;
};
```

- 无 `beforeClose` 的 tab 直接跳过（`undefined` 路径零开销，现行为完全不变）。
- 抛错 = 否决（fail-safe，防误关丢内容）+ `console.error` 留排查线索。

### addTab 数组拼接（merge 语义特判，按函数引用去重）

现有 merge `{ ...prev, ...next }` 中唯独 `beforeClose` 需拼接而非覆盖：

- `prev.beforeClose` 与 `next.beforeClose` 皆存在 → concat 后**按函数引用去重**
  （`filter((f, i, a) => a.indexOf(f) === i)`）。模块按 oj-wiki 模式（useEffect + addTab）
  在 keep-alive 每次重新挂载时重挂守卫，去重保证同一函数引用（`useCallback` 稳定）重复
  注册不叠加——否则守卫数组随挂载次数单调增长，点一次关闭弹 N 个确认框。
- `next.beforeClose === undefined` → 不动 prev（与现有 merge 语义一致）。
- `next.beforeClose === null` → 清除该 tab **全部**守卫（含其他模块注册的）；
  文档须明确此语义，避免模块 B 卸载清理时误清模块 A 的守卫。
- **守卫身份约定**：去重按函数引用判定，模块须以稳定 `useCallback` 引用注册守卫
  （每次渲染 new 闭包的去重预期不成立），写进 devkit 手册守卫小节。

### 五个关闭动作改 async

`removeTab` / `closeRightTabs` / `closeLeftTabs` / `closeOtherTabs` / `closeAllTabs`
原地改 async，签名返回 `Promise<void>`；内部先算受影响 key 集合，过 `guardClose`
后才落状态变更（**精确删除获批的 key 集合**，见下）；否决 = 静默 return（fire-and-forget 调用方零感知、无 unhandled rejection）。

- 受影响集合：removeTab=key；closeRightTabs=key 右侧；closeLeftTabs=key 左侧（不含 home）；
  closeOtherTabs=除 key/home 外全部；closeAllTabs=除 home 外全部。
- 首页守卫沿用 `import.meta.env.VITE_BASE_HOME_PATH`（**不采用 PR 的 `"/home"` 硬编码**），
  home 不在任何受影响集合。
- 事务式：任一守卫否决 → 整批取消，无半关状态。
- **TOCTOU 防护（评审 m1）**：守卫通过后**精确删除获批的 key 集合**，不对 live state
  重算——await 期间（秒级弹窗）用户新开 tab 若落在原集合区间内，对当时状态重算的旧实现
  会把它一并关掉。五个动作收敛为同一条「算集合 → 守卫 → 精确删集合」路径，
  实现更简、语义兑现「事务式」承诺。
- await 守卫期间页签仍在、`openTabs` 未变，组件保持挂载，模块可安全弹窗。
- 批量关闭 N 个带守卫 tab 会**串行弹 N 个确认框**——顺序 await 的语义正确结果，
  实施时不得「优化」为并发弹窗。
- **`resetTabs` 显式绕过守卫（评审 m2）**：`resetTabs` 唯一调用点是 `auth.ts:90`
  的 logout（含 401 强制下线）。罩守卫会让会话已死时的确认框卡死下线链路；
  故 resetTabs 保持同步、不过守卫（fail-open，保下线），写进 BDD 用例。
- **调用点核实（主会话补查 + 工程师评审复核一致）**：五个动作的全部调用点为
  `use-dropdown-menu.tsx` actions 映射（116–120 行）与 `handleEditTabs` → `onClickMenu`
  （layout-tabbar/index.tsx:84），均 fire-and-forget 忽略返回值，async 化非破坏；
  web/ 与 apps/ 无任何调用方。tabbar 自动导航由 activeKey 驱动：守卫否决 → activeKey
  不变 → 不导航（正确语义）；守卫通过 → 删除完成后导航。
- **并发双击去重（评审 m5）**：快速两次触发同一页签关闭会跑两遍守卫、弹两个确认框。
  store 内维护 per-key in-flight Set：某 key 已有进行中的关闭流程时，后续触发直接忽略
  （流程结束 finally 移除）。
- **顺手修复（评审 n1）**：`tabs.ts` 现有 `state.openTabs.get(homePath)!` 非空断言
  （home 缺失的边缘态会把 undefined 塞进 Map），async 化放大该窗口——改为存在才 set。
- **文档注明（评审 n3）**：`resetTabs`（登出/401 下线）清空全部页签，守卫随之消失，
  模块下次挂载时重挂。

### TabsAction 接口同步

五个关闭动作签名改 `Promise<void>`，其余不变。

### 持久化说明

`beforeClose` 是函数，persist 的 `JSON.stringify` 天然丢弃——会话恢复后守卫不复活。
模块须在 `onInit`/页面 effect 里重挂（oj-wiki 的 useEffect + addTab 模式即每次挂载重挂）。
`partialize` 与 storage 序列化无需改动。

## Item 4 — `ojm api` 生成目录 `client` → `__client`（需求方追加）

**动机**：`client/` 是框架生成物（api.ts / api.schemas.ts 等，勿手改），但名字太通用，
易与业务自建目录混淆，也不像「框架私产」。改名 `__client`（双前导下划线标记生成物，
与 oj 侧 `_shared` 私产目录风格同族）。安全核对：`__client` 无尾下划线，不满足 oj
`_name_` 路径参数判定（须整段单下划线包裹），保持字面；前端模块目录本就不参与
oj 路由，无路由影响。

**改动面**：
- `packages/cli/src/contract/run.ts`：契约发现路径
  `web/src/<模块>/client/contract.ts` → `__client/contract.ts`；client 发射目标目录
  `web/src/<模块>/client/` → `__client/`。
- **发现兼容**：过渡期 `client` 与 `__client` 都认（优先 `__client`，命中旧名打
  deprecation 提示指迁移指引），存量工程不炸；新生成一律 `__client`。
- **存量全量迁移**（约 62 个引用、7 个模块目录）：模板
  `web/src/notification/client/`、dogfooding `web/home/client/`、
  `apps/playground{,-oj}` 各模块 client 目录——目录改名 + 全部 import 路径更新
  （`./client/api` → `./__client/api`）。
- 文档同步：`docs/devkit/manual.md`、`docs/oj-api-dev/` 中 `client/` 路径全改。
- CHANGELOG 记 breaking（模块内 import 路径变化，存量工程需跟随改名或依赖发现兼容）。
- 测试：run.ts 发现逻辑双形态用例（新名优先、旧名兼容 + 提示）、emit 目标目录断言。

## 测试（TDD/BDD）

先写 BDD 用例文档（`docs/` 日期前缀），再实现。vitest 新增 tabs 守卫用例：

1. 未声明 beforeClose → 五个动作行为与现版本完全一致（回归基线）。
2. 单守卫 true 放行 / false 否决（页签保留、activeKey 不变）。
3. 数组守卫顺序执行、任一 false 短路整批取消。

5. 批量动作（右侧/左侧/其他/全部）事务性：任一否决则一个都不关。
6. addTab 拼接 / `undefined` 不动 / `null` 清除（含「清除含他人守卫」语义）。
7. 首页豁免：home 不在受影响集合、removeTab(home) 不触发守卫（显式 Given/When/Then）。
8. await 期间页签仍在 openTabs（组件挂载语义）。
9. **重复注册去重（评审 m5）**：同一函数引用重复 addTab 不叠加；不同函数 concat 累积。
10. **`resetTabs` 绕过守卫（评审 m2）**：带守卫 tab 存在时 resetTabs 直接清空、不弹确认。
11. **TOCTOU（评审 m1）**：守卫 await 期间新开 tab 落在原集合区间，关闭完成时该 tab 不受影响。
12. **并发去重（评审 m5）**：同一 key 关闭流程进行中再次触发被忽略，守卫只跑一次。
13. **边界（评审 n4）**：removeTab 不存在的 key 无守卫无副作用；`null` 清除后再注册的序列正确。

Item 1/2 验收：`pnpm test`、`pnpm typecheck`、`pnpm lint`、e2e notification 用例回归。
