# ojm 0.1.18 设计：oj 0.1.69 对齐 + 通知模板同步 + beforeClose 标签守卫

日期：2026-10-14
分支：`feat/ojm-0.1.18`
锁步发版：`@oj-module/runtime` 0.1.17 → 0.1.18，`@oj-module/cli` 0.1.17 → 0.1.18

## 背景

1. **oj 发布 0.1.69**（repo 门禁钉在 0.1.50）。其中 v0.1.64 引入**嵌套 handler 组**，
   官方手册给出明确的 DDD 落点映射（限界上下文=模块、聚合根=实体组、同聚合多动词
   应收进单文件嵌套组而非动词子目录）。模板 api.ts 全部是动词目录形态，需按 DDD 判据 reshape。
2. **runtime 通知铃已升级**（f05b3deb、628e31cc：按人通知 + 广播表 + push/del 原语 +
   markRead 归属 403），但 init 模板的后端只同步了 client/contract，后端 handler、
   `_shared`、migrations 0002/0003 均缺失，`ojm init` 出来的工程通知面是坏的。
3. **模块需要拦截标签页关闭**（oj-wiki 已落地参考实现并提 PR）：有未保存改动时
   弹确认框，removeTab 先删页签再导航会导致 keep-alive 缓存销毁、组件卸载，
   `useBlocker` 来不及触发。正确做法：运行时真正移除页签**之前** await 模块守卫。

## Item 1 — oj 0.1.69 对齐 + 全模板 DDD 改造

### 版本与门禁

- `packages/cli/src/vendor.ts`：`MIN_OJ_VERSION` 0.1.50 → **0.1.69**（既定政策：钉最新发布版）。
- playground-oj `bin/` vendored oj 升 0.1.69（`ojm vendor` / `.oj-version`）。
- 模板 `api/config.yaml` 核对：mounts 模型（0.1.58）已采用；0.1.59–0.1.69 无新增必填配置项
  （嵌套组、统一占位符、`default` 注解均为代码层特性）。config.yaml 注释补充 0.1.64 嵌套组说明。

### api.ts reshape 原则

依据手册判据：**同聚合操作进同一实体组，不同聚合才拆目录**。组名 = 路径段，
故路由路径不变、`routes.json` 不变、`ojm api --check` 双向对账预期自然保持全绿。

| 模块 | 现状（动词目录） | DDD 形态（嵌套组，路由路径全部不变） |
|---|---|---|
| `notification` | `notifications/{api.ts(get), read/, read-all/, clear/}`、`push/`、`push-broadcast/`、`del/` | 模块根单文件 `api.ts`：`notifications` 组（get + read/read-all/clear 子组）+ `push`/`push-broadcast`/`del` 各为单动词组；删除原动词子目录；`_shared/` 保留 |
| `auth` | `login/`、`logout/`、`refresh/` | 模块根单文件 `api.ts`：`login`/`logout`/`refresh` 三个单动词组（会话聚合的三操作）；`_shared/session.ts` 保留 |
| `personal-center` | `upload/api.ts` | **不变**——单聚合单端点，已是最简形态（手册判据：≤3 动词单一聚合可平铺/单文件） |
| `_platform` | 仅 schema/migrations/seed，无 handler | **不变**——无 api.ts 可 reshape |
| `notifications`（root 兜底） | 单文件 get | 不变（单端点，`.ojm-api-exempt.json` 豁免照旧） |
| `web` | manifest-only | 不变（无 handler，本就豁免） |

playground-oj 额外的 `demo/`、`home/`、`system/` 模块按同一判据 reshape（system 为
主要工作量，实施计划中逐聚合拆分）。`_shared/` 目录不受嵌套组影响（无尾下划线，
不会被当成 `_name_` 路径参数）。

**注意**：oj 手册明确嵌套组上限 4 层、`route`/`schema` 为保留键；改造不得触碰这些红线。
release 下路由事实唯一来源是 `routes.js`——playground-oj 若发 release 产物需重新 `oj build`，
dev 形态无此步骤。

## Item 3 — 标签页关闭前守卫 `beforeClose`

采用 oj-wiki PR 形态 + 数组注册增量。改动文件：`packages/runtime/src/store/tabs.ts`。

### 类型

```ts
export type BeforeTabCloseGuard = () => boolean | Promise<boolean>;

export interface TabItemProps extends Omit<TabPaneProps, "tab"> {
    key: string;
    label: React.ReactNode;
    draggable?: boolean;
    historyState?: Record<string, any>;
    /**
     * 关闭该标签页（含关闭右侧/左侧/其他/全部）前调用，顺序 await。
     * - 返回 false / reject / Promise<false> ⇒ 中止本次关闭（标签页保留）。
     * - 返回 true / Promise<true> ⇒ 允许关闭。
     * 数组注册：多守卫顺序执行，任一否决即整批取消。
     */
    beforeClose?: BeforeTabCloseGuard | BeforeTabCloseGuard[];
}
```

`TabStateType extends Omit<TabItemProps, "label">` 自动继承。

### guardClose（模块作用域，与 store 同文件）

```ts
const guardClose = async (get: () => TabsStore, keys: string[]): Promise<boolean> => {
    for (const key of keys) {
        const fn = get().openTabs.get(key)?.beforeClose;
        if (!fn) continue;
        const fns = Array.isArray(fn) ? fn : [fn];
        for (const f of fns) {
            try {
                if (!(await f())) return false;
            }
            catch (e) {
                console.error("[tabs] beforeClose 守卫抛错，按中止关闭处理", e);
                return false;
            }
        }
    }
    return true;
};
```

- 无 `beforeClose` 的 tab 直接跳过（`undefined` 路径零开销，现行为完全不变）。
- 抛错 = 否决（fail-safe，防误关丢内容）+ `console.error` 留排查线索。

### addTab 数组拼接（merge 语义特判）

现有 merge `{ ...prev, ...next }` 中唯独 `beforeClose` 需拼接而非覆盖：

- `prev.beforeClose` 与 `next.beforeClose` 皆存在 → concat 成扁平数组（多模块叠加注册）。
- `next.beforeClose === undefined` → 不动 prev（与现有 merge 语义一致）。
- `next.beforeClose === null` → 清除（显式解绑全部守卫）。

### 五个关闭动作改 async

`removeTab` / `closeRightTabs` / `closeLeftTabs` / `closeOtherTabs` / `closeAllTabs`
原地改 async，签名返回 `Promise<void>`；内部先算受影响 key 集合，过 `guardClose`
后才落原有同步变更；否决 = 静默 return（fire-and-forget 调用方零感知、无 unhandled rejection）。

- 受影响集合：removeTab=key；closeRightTabs=key 右侧；closeLeftTabs=key 左侧（不含 home）；
  closeOtherTabs=除 key/home 外全部；closeAllTabs=除 home 外全部。
- 首页守卫沿用 `import.meta.env.VITE_BASE_HOME_PATH`（**不采用 PR 的 `"/home"` 硬编码**），
  home 不在任何受影响集合。
- 事务式：任一守卫否决 → 整批取消，无半关状态。
- await 守卫期间页签仍在、`openTabs` 未变，组件保持挂载，模块可安全弹窗。

### TabsAction 接口同步

五个关闭动作签名改 `Promise<void>`，其余不变。

### 持久化说明

`beforeClose` 是函数，persist 的 `JSON.stringify` 天然丢弃——会话恢复后守卫不复活。
模块须在 `onInit`/页面 effect 里重挂（oj-wiki 的 useEffect + addTab 模式即每次挂载重挂）。
`partialize` 与 storage 序列化无需改动。
