# ojm 帮助信息按子命令分组（cac 渲染）

- 日期：2026-10-23 08:27
- 分支：refactor/ojm-help-cac
- 状态：已完成（2026-10-23 08:40）

## 需求

`ojm --help`（`packages/cli/src/usage.ts` 的 `usageText()`）当前是平铺的命令清单，命令多时难以速查。要求：

1. 顶层帮助按子命令分组展示（如：工程脚手架 / 开发与构建 / 市场生命周期 / 签名发布 / 本地市场模拟 / oj 透传）。
2. 采用 [cac](https://github.com/cacjs/cac) 进行帮助渲染修正。

非目标（明确不做）：

- 不重写 dispatch：`index.ts` 的 switch 分发与各命令自定义参数解析（`args.ts` / `parseXxxArgs`）保持不变，cac 只负责帮助文本渲染，不参与参数解析与命令执行。
- 不改 `ojm <cmd> --help` 的详版文案：`COMMAND_HELP` 的多行详解保留原样。

## 方案

- `usage.ts` 内建命令注册表（syntax + 一句话描述 + 分组），用 cac 实例渲染每组命令列表（`cli.help(cb)` 捕获 helpSections 而非打印），组间加中文分组头拼接。
- `getCommandHelp` / `resolveHelpRequest` 行为不变，`index.ts` 零改动。
- 新增依赖：`cac`（直接声明在 `packages/cli/package.json`，不入 catalog——catalog 仅收 SHARED_DEPS + 构建工具）。

## 分组

| 分组 | 命令 |
| --- | --- |
| 工程脚手架 | init, new |

## 问题记录

1. **cac 的 outputHelp 只走 console.log**（反常规：无返回帮助文本的 API），help 回调只能改 section 不能拦截输出。对策：`renderGroup` 内临时静默 `console.log`，经 `cli.help(cb)` 捕获 sections 后自行拼接。局限：并发打印会被吞——usageText 是纯帮助渲染，调用期无其它输出，可接受。
2. **catalog 纪律由 eslint 强制**（`pnpm/json-enforce-catalog` + `pnpm/yaml-no-unused-catalog-item`），与 pnpm-workspace.yaml 注释「catalog 仅收 SHARED_DEPS」的字面约定冲突——实际规则是「凡依赖必入 catalog」。cac 已入 catalog。
3. **`pnpm typecheck` 默认堆 OOM**（tsc 全仓 4GB 不够，exit 134），基线（改动前）同样复现，非本次引入。`NODE_OPTIONS=--max-old-space-size=8192 pnpm typecheck` 通过。

## 总结

本阶段将 `ojm --help` 从平铺清单改为 7 组分组索引（工程脚手架 / 开发与构建 / 清单与诊断 / 方案市场 / 发布与签名 / 本地市场模拟 CDN / oj 透传），每组经 cac 实例渲染命令列表（对齐排版），组头中文标注；`--version` 与 `--help` 提示作页脚。单命令详解（COMMAND_HELP）与 dispatch（index.ts 零改动）均不受影响。关键过程：先写分组断言测试（红）→ 实现 HELP_GROUPS 注册表 + renderGroup（绿）→ 契约测试 dev 快捷键断言迁往 `getCommandHelp("dev")`。耗时约 15 分钟（含 pnpm install 与全量测试）。
