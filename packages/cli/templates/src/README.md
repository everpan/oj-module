# src/ 目录说明（动手前必读）

这个目录里有两类东西，规矩不一样。

## 框架自带的模块（不许改）

- `src/app/` —— 框架内置页面与后端（登录、首页、个人中心、通知、系统管理、认证等）
- `src/oj-market/` —— 解决方案市场

它们由上游统一维护、跟着框架版本走。**请不要修改、也不要删除这里的文件**：

- `ojm build` 打包前会逐文件核对这两个目录，发现与官方版本不一致（改过、删过、
  或多出文件）会**直接拒绝构建**，并列出差异清单。
- 为什么这么严：你今天改一行，下次升级就对不上——轻则构建失败，重则升级后
  功能悄悄丢失。上游修过的 bug，会在你本地"复活"。
- 想改功能、加需求？给上游提 issue，等新版本下发后运行：

  ```
  ojm init --yes
  ```

  它会把这两个目录恢复成当前版本的官方内容。注意：**会丢弃你在里面的本地修改**，
  执行前先备份。你自己的模块和 config.yaml 等工程配置不受影响。
- 真的不想要某个自带能力？在 `web.config.ts` 里把对应条目写 `enabled: false`，
  不要删目录。
- 删除 `src/.ojm-builtin.json` 会整个关掉上面的检查——不建议，出了问题没人替你兜底。

## 你自己的模块（随便改）

- `src/<你的模块名>/` —— 用 `ojm new <名字>` 生成，或手工建 `src/<名字>/{api,web}`。

这里是你的地盘：框架不检查、也不会覆盖。

## 一句话总结

> `src/app` 和 `src/oj-market` 是"公家"的，`src/` 下其他目录是你自己的。
> 公家的不许动（动了 `ojm build` 会拦）；要动找上游；升级后跑 `ojm init --yes` 同步。
